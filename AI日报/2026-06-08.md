### [Simon Willison: 用 MicroPython + WASM 打造安全的 Python 代码沙箱](https://simonwillison.net/2026/Jun/6/micropython-in-a-sandbox/#atom-everything)
**原文**: Simon Willison's Weblog

Simon 发布了一个名为 `micropython-wasm` 的 Python 包，在 WebAssembly 沙箱中运行 MicroPython 解释器。核心思路是用 wasmtime 在服务端执行不受信任的 Python 代码，同时提供 CPU/内存限制、严格的文件和网络访问控制，以及宿主函数暴露能力。

最巧妙的设计是持久化解释器状态：MicroPython 在 WASM 内部的一个线程中运行，通过宿主函数 `__session_next__()` 阻塞等待新代码，再用 `eval()` 执行，从而实现跨多次调用的变量和函数驻留。宿主函数通过 78 行 C 代码编译进 WASM blob 实现。项目已发布到 PyPI，并集成到 Datasette Agent 中作为代码执行插件。Simon 坦承这是"vibe-coded"的产物，但强调 WASM 的隔离性意味着即使 C 代码有缺陷，最坏情况也只是执行失败抛异常，不会危及宿主系统。

### [OpenAI 正式推出 Lockdown 模式：防止提示注入的最后一环](https://simonwillison.net/2026/Jun/5/openai-help-lockdown-mode/#atom-everything)
**原文**: Simon Willison's Weblog

OpenAI 向个人账户和企业版推出 Lockdown Mode，旨在阻止提示注入攻击的最后阶段——数据外泄。该模式限制 ChatGPT 的外发网络请求，防止攻击者通过注入将敏感数据传输到外部。需要注意的是，它不阻止注入本身（注入仍可通过缓存的网页或上传文件进入），但切断了数据被偷走的通道。Simon 认为这有效应对了他之前提出的"致命三角"（访问私密数据 + 工具调用能力 + 提示注入风险）中最危险的环节。

## 技术视野

### [Meta: 数据中心瞬间断电的容灾验证实践](https://engineering.fb.com/2026/06/03/data-center-engineering/lights-out-systems-on-validating-instant-power-loss-readiness/)
**原文**: Engineering at Meta

Meta 工程团队分享了"瞬时断电风暴"（Instantaneous PowerLoss Storm）测试范式——处理零预警数据中心断电的终极防线。文章的核心技术亮点：

- **纵深防御体系**：从机房电力设施到服务器机架，从存储到 Twine 容器编排器，每一层都内建了断电容忍能力。电池备份 + Power Loss Siren 机制保证内存数据持久化，Unavailability Events 提供跨区域的异步信号传递。
- **解决循环依赖**：在一个区域整体断电后启动（bootstrapping）时，编排器控制面服务之间存在鸡生蛋蛋生鸡的循环依赖。Meta 通过 CI/CD 中的 Belljar 测试持续检测关键启动依赖，并开发了 Twine Recovery Kit 作为"跳线启动"能力的兜底方案。
- **解决回旋镖问题**：用于编排关机和恢复的 Unavailability Events 信号会把控制面服务自己也关掉，导致出现僵尸服务。解决方案是让控制面服务直接忽略断电相关的关机信号。
- **渐进式验证**：从影子区域测试→最小生产区域→大型关键生产区域，逐步推进，最终在承载存储、AI、数仓负载的大区域成功完成断电演练。Meta 的哲学是"慢即是稳，稳即是快"——可靠性和增长速度是同一枚硬币的两面。
